## ЗАДАЧА 4 — Форма заявки (V) — `POST /api/lead`

Поля: `name` (required), `phone` (required, type=tel), `interest` (select), `comment` (textarea, maxlength=600), **`website` (HONEYPOT)**, `consent` (checkbox, required). `<form novalidate>` без action/method → обработка JS.

### 4.1 Пустая отправка
Тексты ошибок: **«Укажите имя», «Укажите телефон», «Отметьте согласие на обработку данных»** — выводятся в контейнере `role="alert"`.
Подсветка: поля с ошибкой получают `aria-invalid="true"` и красную рамку (rgb(156,47,30)).
Доступность: `aria-describedby` указывает на id блока ошибки (`…-name-error`, `…-phone-error`, `…-consent-error`). ✅ Отправки не произошло, модалка осталась открытой.

### 4.2 Невалидные данные
| Ввод | Реакция |
|---|---|
| Имя «A» / «Т» (1 символ) | `aria-invalid=true`, «Слишком короткое имя» |
| Телефон «abc» | инпут вычищает буквы → значение "" → «Укажите телефон» |
| Телефон «123» | автоформат → «+7 123», ошибка «Проверьте номер: нужен формат +7 XXX XXX XX XX» |
| E-mail «не-емейл» | **поля e-mail в форме нет** — проверка неприменима (NV) |
| Имя `<script>alert(1)</script>` | ошибки НЕТ — значение принимается как есть (клиентская санитизация отсутствует) |
| Имя «😀» | ошибки нет, принимается |
| Комментарий 500 символов | принимается (лимит maxlength=600) |

### 4.3 Валидная отправка (ровно 1 раз)
- URL запроса: **`/api/lead`**, метод **POST**
- Payload: `{"name":"ТЕСТ АУДИТ","phone":"+77001234567","interest":"","comment":"","subject":"","source":"header","consent":true,"website":""}`
- HTTP-статус: **200**
- Тело ответа: **`{"ok":true,"delivered":false}`**
- UI: кнопка меняется на **«Отправляем…»** и становится **disabled=true**; после — экран успеха **«Заявка отправлена. Менеджер отдела продаж свяжется с вами в рабочее время.»** + кнопки «Позвонить сейчас», «Написать в WhatsApp», «Отправить ещё одну заявку».

⚠ `delivered:false` — сервер отвечает ok, но доставка не выполнена (лид, вероятно, нигде не сохраняется). FINDING.

### 4.4 Двойная отправка
3 синхронных программных клика по submit → **3 запроса POST /api/lead** (все 200). Идемпотентности/дедупликации нет; защита только за счёт асинхронного `disabled`. Реальный двойной клик человека, скорее всего, блокируется, но код-уровневой защиты нет. FINDING.

### 4.5 Honeypot
Есть: `input name="website"`, `tabindex="-1"`, `autocomplete="off"`, визуально скрыт (высота 0, `offsetParent===null`). ✅

## СПИСОК НАЙДЕННЫХ ПРОБЛЕМ

**[P1] Заявки не доставляются**
Где: форма заявки → `POST /api/lead`. Что: сервер отвечает `{"ok":true,"delivered":false}`, при этом UI показывает «Заявка отправлена».
Воспроизвести: открыть форму → заполнить имя+телефон+согласие → отправить → в ответе `delivered:false`.
Ожидаемо: лид доставляется (CRM/почта/вебхук) → `delivered:true`. Фактически: `delivered:false` — лид теряется.
Причина: интеграция доставки не настроена/падает, но API маскирует это успехом. Исправить: вернуть ошибку при недоставке или реально настроить доставку; не показывать успех при `delivered:false`.

**[P2] Нет защиты от двойной отправки формы**
Где: `/api/lead` + обработчик формы. Что: 3 быстрых клика → 3 POST. Воспроизвести: в модалке заявки 3× подряд submit. Ожидаемо: 1 запрос / идемпотентность. Фактически: 3 запроса. Причина: защита только через async `disabled`. Исправить: блокировка в обработчике + idempotency-key/серверная дедупликация.

**[P2] Разные 404 и дефолтная англоязычная 404 без навигации**
Где: несуществующие маршруты верхнего уровня. Что: `/ru/<что-угодно>` → дефолтная Next.js 404 (English, без шапки, без `<main>`, без ссылок). Воспроизвести: открыть /ru/ne-stranica. Ожидаемо: единый локализованный 404 с навигацией (как для /ru/apartments/net-takoy). Фактически: два разных поведения. Причина: отсутствует глобальный `app/not-found` (есть только сегментный). Исправить: добавить корневой localized not-found.

**[P2] На странице документов нет предпросмотра документов**
Где: /ru/documents. Что: клик по документу открывает форму заявки, а не просмотр/скачивание файла; текст обещает «открыть его просмотр». Воспроизвести: /ru/documents → клик по «Разрешение на строительство». Ожидаемо: открывается PDF/предпросмотр (или явное «Запросить документ»). Фактически: форма заявки. Причина: файлы не подключены. Исправить: подключить PDF либо изменить текст.

**[P3] Нет активного состояния пункта меню**
Где: шапка. Что: ни `aria-current`, ни класса active у текущего пункта. Воспроизвести: перейти в любой раздел. Ожидаемо: подсветка активного пункта + `aria-current="page"`. Фактически: отсутствует. Исправить: добавить по текущему pathname.

**[P3] Кнопка закрытия просмотрщика планировок подписана неверно**
Где: /ru/floorplans, модалка плана. Что: ✕-кнопка имеет `aria-label="Планировка"` вместо «Закрыть». Воспроизвести: открыть план → инспектировать кнопку вверху справа. Ожидаемо: `aria-label="Закрыть"`. Фактически: «Планировка» (скринридер вводит в заблуждение). Исправить: поправить label.

**[P3] Фокус не возвращается на триггер после закрытия модалок**
Где: модалка заявки, просмотрщик плана. Что: после Escape фокус падает на `<body>`. Ожидаемо: фокус возвращается на кнопку, открывшую модалку. Фактически: `<body>`. Исправить: сохранять/восстанавливать `document.activeElement`.

**[P3] Мелкие замечания**
- `htmlLang` EN = `en`, RU=`ru-KZ`, KZ=`kk-KZ` (непоследовательный формат).
- Маркетинговое «В ПРОДАЖЕ 128» vs «Найдено 149» в каталоге по умолчанию.
- Имя принимает `<script>alert(1)</script>` без клиентской валидации/санитизации (риск при выводе на бэкенде).
- Ссылки `_blank` (WhatsApp) без `rel="noopener"` в атрибутах (проверено: rel=null).

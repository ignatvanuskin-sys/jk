# QONYS RESIDENCE — цифровой отдел продаж ЖК

Production-ready сайт жилого комплекса для рынка Казахстана: RU / KZ / EN, каталог квартир
с фильтрами, «шахматка» выбора квартиры, планировки в SVG с полноэкранным просмотром,
ипотечный калькулятор с программами РК, ход строительства, документы, лид-формы с реальным
backend-роутом.

**Статус: демонстрационная сборка.** Всё, что описывает сам ЖК (название, цены, площади,
адреса, телефоны, сроки), — заполнители. Они внутренне согласованы и реалистичны, но не
являются реальными данными. Порядок замены — в разделе «Как подставить реальные данные».

## Стек

| Слой | Технология | Почему |
|---|---|---|
| Фреймворк | Next.js 15 (App Router) + React 19 | SSG для всех страниц: SEO, sitemap, schema.org, мгновенная выдача |
| Язык | TypeScript (strict) | Три локали проверяются компилятором: пропущенный ключ — ошибка сборки |
| Стили | Tailwind CSS v4 (CSS-first `@theme`) | Дизайн-токены в одном месте, почти нет собственного CSS |
| Шрифты | `next/font/google` — Cormorant + Inter | Самохостинг, без сторонних запросов; кириллица + cyrillic-ext (казахские ә, ғ, қ, ң, ө, ұ, ү, һ, і) |
| Анимации | IntersectionObserver (собственный `Reveal`) | Один эффект — не тянем библиотеку на 30–40 КБ |
| Картинки | `next/image` + `sharp` (prebuild) | AVIF/WebP, явные размеры, blur-плейсхолдеры, CLS = 0 |
| Графика планов | Собственный SVG-рендерер | Планы строятся из той же геометрии, что и площади в каталоге |

Внешних рантайм-запросов нет: шрифты, изображения и вся графика отдаются с того же домена.

## Быстрый старт

```bash
npm install
npm run prepare:images     # оптимизация /public/images/raw → /public/images + blur-плейсхолдеры
npm run dev                # http://localhost:3000 → редирект на /ru
```

Production-проверка:

```bash
npm run build
npm run start              # http://localhost:3000
```

Проверки:

```bash
npm run typecheck          # tsc --noEmit
npm run check:content      # запрещённые маркеры + паритет трёх словарей
npm run qa                 # аудит по sitemap против запущенного сервера (все страницы, ссылки, SEO, a11y)
```

## Слой данных — единственное место с фактами

Ни один компонент не содержит данных о проекте. Всё живёт в `src/data/`:

| Файл | Что внутри |
|---|---|
| `project.ts` | название, город, сроки, базовая цена/м², корпуса, контакты, паркинг, коммерция, флаг `DEMO` |
| `apartments.ts` | инвентарь квартир: детерминированная генерация из фиксированного seed + агрегаты |
| `floorplans.ts` | геометрия планировок в метрах; площади выводятся из неё, а не задаются отдельно |
| `plan-summaries.ts` | компактная проекция планов для клиентского просмотрщика |
| `infrastructure.ts` | объекты инфраструктуры (только типы, без вымышленных названий) и их позиции на схеме |
| `construction.ts` | фазы строительства и ежемесячные отчёты; проценты выводятся из фаз |
| `mortgage-programs.ts` | программы финансирования РК с источниками и датами |
| `documents.ts` | пакет документов: что это, что проверять, статус раскрытия |
| `developer.ts` | профиль застройщика; награды намеренно не выдуманы |
| `media.ts` | список изображений + alt-тексты на трёх языках |
| `image-meta.ts` | **генерируется** `prepare:images`: размеры и blur-плейсхолдеры |

Ключевое архитектурное решение: **площади и цены считаются, а не хранятся**. Площадь квартиры —
это сумма площадей помещений из геометрии плана; цена — площадь × базовая ставка × коэффициент
этажа × коэффициент вида. Поэтому каталог, карточка, «шахматка» и план не могут разойтись.

## Как подставить реальные данные

1. **`src/data/project.ts`** — название, класс, сроки, базовая цена, корпуса, контакты. Поставьте
   `DEMO.isDemo = false` и удалите баннеры-заглушки.
2. **`src/data/apartments.ts`** — замените `buildInventory()` на выборку из CRM/API или на
   загруженный массив. Формат `Apartment` описан в том же файле.
3. **`src/data/floorplans.ts`** — либо перенесите реальные размеры в геометрию, либо отрисуйте
   план как изображение (тогда `FloorPlanSvg` заменяется на `next/image`).
4. **`src/content/seo.ts`**, **`src/content/privacy.ts`** — тексты под реальный проект; политику
   обязательно проверить юристом.
5. **`public/images/raw/`** — положите реальные визуализации и фотографии под теми же именами и
   выполните `npm run prepare:images`.
6. **Документы** — в `src/data/documents.ts` замените описания на реальные файлы и добавьте
   ссылки на PDF.
7. Уберите все `<DemoNotice>` (или отключите их одним флагом `DEMO.isDemo`).

## Переменные окружения

Скопируйте `.env.example` в `.env.local`. Сайт полностью работает без них.

| Переменная | Назначение |
|---|---|

| `NEXT_PUBLIC_SALES_PHONE` | телефон в шапке, футере и контактах |

## Приём заявок

`POST /api/lead` — настоящий обработчик, а не имитация успеха:

1. ограничение размера тела, парсинг JSON;
2. повторная серверная валидация (клиентская проверка — только UX);
3. проверка honeypot-поля (бот заполняет — заявка молча отбрасывается и не сохраняется);
4. rate limit: 6 заявок с IP за 10 минут;
5. нормализация телефона к `+7XXXXXXXXXX`;
6. доставка во все настроенные каналы и **всегда** запись в `data/leads/leads-YYYY-MM-DD.jsonl`,
   чтобы заявка не потерялась при недоступности канала.

Секреты читаются только на сервере и никогда не попадают в клиентский бандл.

## Доступность, SEO и производительность

- **A11y**: семантические лендмарки, skip-link, один `<h1>` на страницу, focus-trap и Escape в
  модальных окнах, `aria-live` для результатов фильтра, подписи у всех полей, статусы квартир
  не передаются одним лишь цветом, `prefers-reduced-motion` полностью отключает анимации.
- **SEO**: уникальные title/description на каждую страницу и язык, canonical, взаимные hreflang
  (`ru-KZ`, `kk-KZ`, `en`, `x-default`), OG/Twitter, sitemap с alternates, robots, JSON-LD
  (`Organization`, `ApartmentComplex`, `RealEstateAgent`, `RealEstateListing`/`Offer`,
  `BreadcrumbList`, `FAQPage`).
- **Performance**: все страницы статические, шрифты самохостингуются, hero — единственное
  `priority`-изображение, анимации только на `opacity`/`transform`, планы — векторные SVG
  (не растровые картинки), сторонних скриптов нет.

Автоматическая проверка SEO/a11y/битых ссылок: `npm run qa` — обходит все страницы из
`sitemap.xml`, проверяет `html lang`, единственный `<h1>`, длину title/description, canonical,
hreflang, OG/Twitter, парсинг JSON-LD, `alt` у изображений, скачки уровней заголовков, подписи
у полей формы, наличие `<main>`/шапки/футера/skip-link, а затем обходит каждую внутреннюю ссылку.
Отчёт пишется в `qa-report.md` и `qa-report.json` (в git не хранится — воспроизводится командой).

Актуальный прогон на этой сборке: **687 страниц, 0 замечаний, 0 битых ссылок из 687**.

## Что не хранится в репозитории

Репозиторий держится компактным: в него не попадают ни исходники зависимостей, ни промежуточные
артефакты. Всё перечисленное воспроизводится командами.

| Не в git | Как получить |
|---|---|
| `node_modules/`, `.next/` | `npm install`, `npm run build` |
| `public/images/raw/media-output/` | промежуточный вывод генерации визуализаций; итоговые файлы уже лежат в `public/images/` |
| `data/leads/` | создаётся при первой заявке на `/api/lead` |
| `qa-report.md`, `qa-report.json` | `npm run qa` |
| `.env.local` | скопировать из `.env.example` |

Исходные изображения `public/images/raw/*.jpg` **в репозитории есть** — без них `npm run prepare:images`
нечего оптимизировать.

## Деплой

Сборка полностью статическая (кроме `/api/lead`), поэтому подходит любой Node-хостинг.
Вариант с Vercel:

```bash
npm i -g vercel
vercel link
vercel env add NEXT_PUBLIC_SITE_URL      # реальный домен
vercel env add NEXT_PUBLIC_SALES_PHONE
vercel env add NEXT_PUBLIC_WHATSAPP
vercel env add NEXT_PUBLIC_SALES_EMAIL
vercel --prod
```

На собственном сервере:

```bash
npm ci
npm run build
PORT=3000 npm run start        # за reverse-proxy (nginx/Caddy) с HTTPS
```

После смены домена обязательно задайте `NEXT_PUBLIC_SITE_URL`: от него зависят `canonical`,
`sitemap.xml` и абсолютные URL в Open Graph.

## Лицензия и статус данных

Код — демонстрационный шаблон для продажи/передачи заказчику. Все данные о самом ЖК
(название, застройщик, БИН, адрес, цены, площади, сроки, телефоны) — **заполнители** и не
описывают реальный объект. Перед публичным запуском их необходимо заменить реальными и
подтверждёнными данными, а текст политики конфиденциальности — проверить юристом.
